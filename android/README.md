# 小音遥控（安卓）

**开 App 就能语音使唤小音，不用开浏览器**：说「小音」唤醒 → 说「放首晴天」→ 手机的 QQ 音乐自动弹出并播放；「暂停」「下一首」也是控手机上的音乐。回复是服务器合成的语音，直接在手机上播出来。

比网页版强一点的地方：用的是前台服务 + 麦克风类型，**锁屏也能继续听**（浏览器做不到）。

**不影响电脑端**：用桌宠、CLI 或电脑网页说话时，歌照旧播在电脑上——服务器按「这次请求是谁发来的」决定在哪播，不靠猜。

## 为什么需要这个 App

网页版做不到「零点击」：浏览器禁止网页在没有用户点击的情况下拉起别的 App（iOS/Android 都是，属安全设计）。而原生 App 用代码调起别的 App 不需要确认——所以「说完话就播」只能靠 App。

## 它是怎么工作的

1. App 通过常驻服务连到电脑上的小音服务器（`/ws/device`，明文 ws，局域网内）
2. 你用**手机**对助手点歌时，服务器把 `{"type":"play","songmid":"...","name":"..."}` 推给 App
3. App 用 `qqmusic://qq.com/media/playSonglist?p={"song":[{"songmid":"..."}],"action":"play"}`
   调起 QQ 音乐播放（这个格式是拿真机逐个试出来的：写成数组形式只会打开 App 不播放）
4. 「暂停/切歌」走 Android 标准媒体控制：拿到 QQ 音乐的 `MediaSession` 直接指挥它
   （QQ 音乐没有公开的控制协议，这是唯一不依赖界面自动化的做法）

## 构建

需要：JDK 17、Android SDK（Platform 36 + Build-Tools 36）。

```bash
cd android
./gradlew assembleDebug
# 产物：app/build/outputs/apk/debug/app-debug.apk
```

首次构建若报「licenses have not been accepted」，先接受一次 SDK 许可协议：

```bash
"<SDK>/cmdline-tools/7.0/bin/sdkmanager.bat" --licenses     # 一路 y
```

国内下载 SDK 慢的话走腾讯镜像：

```bash
sdkmanager.bat --no_https --proxy=http --proxy_host=mirrors.cloud.tencent.com --proxy_port=80 --licenses
```

## 安装

**方式一（推荐）**：把 APK 拷到小音项目的 `web/` 目录下，手机浏览器打开
`https://<电脑IP>:7861/wake-static/xiaoyin-remote.apk` 直接下载安装。

**方式二**：数据线拷进手机，用文件管理器点开安装（需允许「安装未知来源应用」）。

## 连接前：给 7860 放行防火墙（管理员执行一次）

App 直连的是电脑上 `python app.py` 的 **7860**（明文 ws）。Windows 防火墙默认不放行，
不放行就会一直卡在「正在连接」：

```
netsh advfirewall firewall add rule name="小音助手 7860" dir=in action=allow protocol=TCP localport=7860
```

> **别填 7861**。7861 是给手机**浏览器**用的 HTTPS 入口（加密），App 走的是明文 ws，
> 端口填错了连不上。（填错了也没关系，App 会自动把它纠正成 7860 并显示出来。）

## 装完必做的两步设置

App 界面上会实时显示这两项是否已授予（❌ 表示对应功能会静默失效）：

| 权限 | 用途 | 怎么给 |
|---|---|---|
| **显示在其他应用上层** | Android 10+ 禁止后台服务调起别的 App，这是官方留的例外通道 | App 里点「① 授予」按钮，跳到系统设置里打开 |
| **通知使用权** | 才能拿到 QQ 音乐的媒体会话来暂停/切歌 | App 里点「② 授予」按钮，在列表里找到「小音遥控」打开 |
| **麦克风** | 语音助手（说「小音」唤醒） | 点语音助手开关时会自动弹出申请，允许即可 |

**国产 ROM 必做**（荣耀/华为/小米等）：在系统设置里允许本应用**自启动**、**后台运行**，并把电池策略设为**不优化**。
否则常驻服务会被系统杀掉，表现为「用一会儿就断了」「语音助手自己关了」——实测用户的手机就断过。

## 使用

1. 打开 App，点「🔍 **自动发现服务器**」——它会在局域网里广播找电脑上的小音（**推荐**）
   - 电脑换了网络、IP 变了也能找到：App 是从**回复包的来源地址**拿到服务器 IP 的，不用手改配置
   - 电脑上要放行发现端口（管理员执行一次；发现走 UDP，和语音的 TCP 规则是两条）：
     ```
     netsh advfirewall firewall add rule name="小音助手 发现" dir=in action=allow protocol=UDP localport=7863
     ```
   - 找不到就手输地址（形如 `192.168.1.7:7860`，即 `python app.py` 那台机器）
2. 状态显示「已连上小音服务器」（地址会记住，服务被杀掉重启也能自己接上）
3. 点底部「🎙️ **开始对话**」（首次会申请麦克风权限，允许后再点一次）
   - 状态变成「🎙 聆听中 — 说「小音」唤醒」就说明麦克风在工作了
   - **现在不用开浏览器了**：直接说「小音」→ 状态变「🔔 唤醒成功」→ 说「放首晴天」
   - 想要连着问不用每句喊唤醒词，再点一下「🔁 连续」
   - **锁屏也能用**（前台服务 + 麦克风类型，这是 App 相对网页的优势）
4. 手机 QQ 音乐自动播放；接着说「暂停」「下一首」即可

## 界面

上面一个会**呼吸的状态球**，颜色就是当前状态，扫一眼就知道它在干嘛：

| 颜色 | 含义 |
|---|---|
| 灰色 | 没在跑 |
| 紫色（慢呼吸） | 在听，说「小音」唤醒 |
| 绿色（快闪） | 听到唤醒词了，请说话 |
| 橙色 | 在想（识别／生成回复） |
| 蓝色（跟着语速） | 正在说话 |
| 红色 | 出错了 |

中间是**对话气泡**：你说的靠右（紫色），小音回的靠左（白色）。**气泡是配音开始播的那一刻才出现的**，
所以看到的字和你听到的声音是同一句，不会文字先跑出来、声音过几秒才来。

> 界面刷新靠界面自己每 300ms 读一次服务里的状态，**不走广播**。
> 之前用广播有个坑：服务在后台线程 `sendBroadcast`，界面在前台收不到，
> 表现是「对话不刷新，得切出去再回来才更新」。同一个进程里直接读静态字段最稳。

服务器地址和权限收在右上角「⚙ 设置」里，默认不展开。

> 回复的语音由手机播出来；播报中直接说话可以打断（和你打断真人一样）。

## 排查

| 现象 | 原因 |
|---|---|
| 状态一直停在「正在连接 …」 | ①地址填成 7861 了（要用 **7860**）②电脑没跑 `python app.py` ③防火墙没放行 7860 ④手机和电脑不在同一局域网。失败 3 次后状态里会带上原因（`ConnectException`≈没人监听或被拦、`SocketTimeoutException`≈网络不通） |
| 状态一直「连接断开，重连中」 | 同上；另外看通知栏有没有「小音遥控」——没有就说明前台服务没起来，多半是权限被 ROM 拦了 |
| 自动发现「没找到」 | 电脑没跑 `python app.py`、UDP 7863 没放行、或路由器开了 AP 隔离（见下） |
| 同一 WiFi 但连不上 | 有些路由器开了**AP 隔离/客户端隔离**，会禁止设备互相访问——去路由器后台关掉 |
| 点歌后提示「没能调起 QQ 音乐」 | 手机没装 QQ 音乐，或「显示在其他应用上层」没授予 |
| 暂停/切歌提示「没控制成功」 | 「通知使用权」没授予，或 QQ 音乐当前没在播放 |
| 放着放着服务没了 | 系统的后台限制把服务杀了，去设置里允许自启动/后台运行 |
| 点「语音助手」没变成「聆听中」 | 麦克风权限没给全。前台服务要声明 microphone 类型，**系统要求此刻就持有麦克风权限**，没给会直接拒绝（连服务器连接都会一起断）——所以顺序必须是：先允许麦克风，再点开关 |
| 语音助手状态一直是「聆听中」但喊不醒 | 离手机太远/环境太吵；阈值在电脑的 `.env` 里调 `KWS_KEYWORDS_THRESHOLD`（默认 0.25，调低更容易唤醒，如 0.15） |
| 助手播报时自己把自己打断 | 手机外放的声音被麦克风收进去了。代码里已在可用时自动开启系统回声消除（AEC）；机型不支持时戴耳机最稳 |
